# Chapter 11: AI와의 대화 기술

프롬프트 엔지니어링이 AI에게 **무엇을** 요청하는 기술이라면, AI와의 대화 기술은 **어떻게** 대화를 이어가는가에 대한 기술입니다. 바이브 코딩에서 좋은 결과물은 단 한 번의 완벽한 요청이 아니라, 여러 번의 자연스러운 대화에서 나옵니다. 마치 동료 개발자와 함께 일하듯, AI와 대화하며 프로그램을 점진적으로 완성해 나가는 것이 바이브 코딩의 핵심입니다.

이 장에서는 AI와 효과적으로 대화하는 방법을 배웁니다. 대화의 흐름을 이해하고, 컨텍스트를 유지하며, 단계별로 기능을 추가하고, 적절한 피드백을 주는 기술을 익히면 바이브 코딩의 생산성이 크게 향상됩니다.

---

### 학습 목표

이 장을 마치면 다음을 이해할 수 있습니다:

- 단일 요청과 대화형 개발의 차이점과 각각의 장단점
- AI 세션에서 컨텍스트를 유지하며 기능을 확장하는 방법
- 이전 코드를 효과적으로 참조하는 대화 패턴
- 단계별 요청으로 복잡한 프로그램을 점진적으로 만드는 전략
- 긍정적 피드백과 수정 피드백을 적절히 활용하는 기법
- 대화가 길어졌을 때 리셋하고 관리하는 방법

### 11.1 대화의 흐름 이해하기

바이브 코딩에서 AI와의 대화는 크게 두 가지 방식으로 나뉩니다.

#### 방식 A: 단일 요청

한 번의 요청으로 모든 것을 한꺼번에 만들어 달라고 하는 방식입니다.

```
"계산기 만들어줘"
```

이 방식은 간단한 프로그램에는 잘 작동하지만, 복잡한 기능이 필요한 경우에는 결과물의 품질이 떨어질 수 있습니다.

#### 방식 B: 대화형 개발

여러 번의 대화를 통해 프로그램을 점진적으로 발전시키는 방식입니다.

```
1차 대화: "기본 계산기 만들어줘"
2차 대화: "반복 계산이 되게 해줘"
3차 대화: "입력 검증을 추가해줘"
4차 대화: "계산 히스토리를 보여줘"
5차 대화: "결과를 보기 좋게 포맷팅해줘"
```

이 방식은 각 단계에서 결과를 확인할 수 있고, 방향을 조절할 수 있으며, 최종 결과물의 품질이 훨씬 높습니다.

다음 예제에서 두 방식의 차이를 직접 확인해보겠습니다.

---

**예제 11-1: 단일 요청 vs 대화형 개발**

같은 "계산기" 프로그램을 두 가지 방식으로 개발한 결과를 비교합니다. 방식 A는 "계산기 만들어줘"라는 단일 요청이고, 방식 B는 5번의 대화를 거쳐 점진적으로 개선한 결과입니다.

```python
# examples/python/chapter03/ex11_01_single_vs_iterative.py (일부 발췌)

# 방식 A: 단일 요청으로 만든 기본 계산기
def basic_calculator():
    """단일 요청으로 생성된 기본 계산기"""
    num1 = float(input("첫 번째 숫자: "))
    operator = input("연산자 (+, -, *, /): ")
    num2 = float(input("두 번째 숫자: "))

    if operator == "+":
        result = num1 + num2
    elif operator == "-":
        result = num1 - num2
    elif operator == "*":
        result = num1 * num2
    elif operator == "/":
        result = num1 / num2 if num2 != 0 else "오류: 0으로 나눌 수 없습니다"
    else:
        result = "오류: 잘못된 연산자"

    print(f"결과: {result}")


# 방식 B: 대화형 개발로 만든 향상된 계산기
# 1차 대화: 기본 계산기 만들어줘
# 2차 대화: 반복 계산이 되게 해줘
# 3차 대화: 입력 검증을 추가해줘
# 4차 대화: 계산 히스토리를 보여줘
# 5차 대화: 결과를 보기 좋게 포맷팅해줘

def enhanced_calculator():
    """대화형 개발로 만든 향상된 계산기"""
    history = []
    operators = {
        "+": lambda a, b: a + b,
        "-": lambda a, b: a - b,
        "*": lambda a, b: a * b,
        "/": lambda a, b: a / b if b != 0 else None,
    }

    print("\n사용법: 숫자 연산자 숫자 (예: 10 + 5)")
    print("명령어: 'history' = 기록 보기, 'quit' = 종료\n")

    while True:
        user_input = input("계산> ").strip()

        if user_input.lower() == "quit":
            print("\n계산기를 종료합니다.")
            break

        if user_input.lower() == "history":
            if not history:
                print("  아직 계산 기록이 없습니다.")
            else:
                for i, record in enumerate(history, 1):
                    print(f"  {i}. {record}")
            continue

        # 입력 파싱 및 검증
        parts = user_input.split()
        if len(parts) != 3:
            print("  형식: 숫자 연산자 숫자 (예: 10 + 5)")
            continue

        try:
            num1, op, num2 = float(parts[0]), parts[1], float(parts[2])
        except ValueError:
            print("  올바른 숫자를 입력해주세요.")
            continue

        result = operators.get(op, lambda a, b: None)(num1, num2)
        if result is not None:
            expression = f"{parts[0]} {op} {parts[2]} = {result}"
            history.append(expression)
            print(f"  {expression}")
```

```bash
$ python examples/python/chapter03/ex11_01_single_vs_iterative.py --compare
```

**결과:**

```
  ├────────────────┼──────────────┼──────────────┤

```

방식 A의 계산기는 숫자를 입력하고 결과를 보면 바로 프로그램이 종료됩니다. 반면 방식 B의 계산기는 반복 계산, 입력 검증, 히스토리 기능, 깔끔한 포맷팅까지 갖추고 있습니다. 같은 "계산기"를 요청했지만, 대화를 여러 번 주고받으며 다듬은 결과물은 완전히 다른 수준의 프로그램이 됩니다.

> **Tip:** 바이브 코딩에서 대화의 횟수를 아끼려고 하지 마세요. AI와 5번 대화해서 좋은 프로그램을 만드는 것이, 1번 대화해서 부족한 프로그램을 만드는 것보다 훨씬 효율적입니다. 대화는 무료이고, 대화할수록 결과물은 좋아집니다.

### 11.2 컨텍스트 유지의 중요성

AI와의 대화에서 **컨텍스트(context)**란 "AI가 이전 대화 내용을 기억하고 있는 상태"를 의미합니다. 같은 세션 안에서 대화를 이어가면, AI는 이전에 작성한 코드, 사용한 변수명, 프로그램의 구조를 모두 기억합니다. 이것을 활용하면 기존 코드를 깨뜨리지 않으면서 새로운 기능을 자연스럽게 확장할 수 있습니다.

#### 컨텍스트가 유지되는 경우

같은 세션에서 대화를 이어갈 때 컨텍스트가 유지됩니다. 예를 들어 다음과 같은 흐름이 가능합니다.

```
1차: "단위 변환기 만들어줘"
     → AI가 기본 변환 기능이 있는 프로그램 생성

2차: "여기에 히스토리 기능 추가해줘"
     → AI가 기존 코드 구조를 기억하고, 그 위에 히스토리 기능 추가
```

"여기에"라는 단어 하나로 AI가 이전 코드를 참조합니다. 변수명, 함수 구조, 데이터 형식이 모두 일관되게 유지됩니다.

#### 컨텍스트가 끊어지는 경우

새로운 세션을 시작하거나, 대화가 너무 길어져서 이전 내용을 더 이상 기억하지 못할 때 컨텍스트가 끊어집니다.

```
[세션 1] "단위 변환기 만들어줘" → 변환기 코드 생성

[세션 2] "히스토리 기능 추가해줘"
→ AI가 어떤 프로그램에 추가할지 모름!
→ 완전히 새로운 코드를 작성하게 됨
```

컨텍스트가 끊어지면 AI는 이전 코드의 변수명, 함수 구조를 알 수 없으므로 전혀 다른 스타일의 코드를 생성할 수 있습니다.

**예제 11-2: 컨텍스트 유지하며 기능 확장**

이 예제는 기본 단위 변환기를 만든 뒤, 같은 세션에서 "여기에 히스토리 기능 추가해줘"라고 요청하여 기능을 확장하는 과정을 보여줍니다.

```python
# examples/python/chapter03/ex11_02_context_extension.py (일부 발췌)

# [1차 대화] "단위 변환기 만들어줘"
def basic_converter():
    """1차 대화: 기본 단위 변환기"""
    converters = {
        "1": ("km → mile", lambda x: x * 0.621371),
        "2": ("mile → km", lambda x: x / 0.621371),
        "3": ("kg → lb", lambda x: x * 2.20462),
        "4": ("lb → kg", lambda x: x / 2.20462),
        "5": ("°C → °F", lambda x: x * 9 / 5 + 32),
        "6": ("°F → °C", lambda x: (x - 32) * 5 / 9),
    }

    print("\n변환 종류를 선택하세요:")
    for key, (name, _) in converters.items():
        print(f"  {key}. {name}")

    choice = input("\n선택: ").strip()
    name, func = converters[choice]
    value = float(input(f"변환할 값 ({name}): "))
    result = func(value)
    print(f"\n결과: {value} → {result:.2f}")

    }

    history = []  # 히스토리 저장 (2차 대화에서 추가된 부분)

    while True:
        # ... 변환 로직 ...

        history.append({
            "time": datetime.now().strftime("%H:%M:%S"),
```

#### 컨텍스트 유지를 위한 실전 전략

컨텍스트를 효과적으로 유지하기 위한 몇 가지 전략을 정리합니다.

| 전략 | 설명 | 예시 |
|------|------|------|
| **같은 세션 유지** | 프로그램이 완성될 때까지 세션을 유지 | 브라우저 탭을 닫지 않기 |
| **명시적 참조** | "여기에", "이 코드에" 등의 참조어 사용 | "이 함수에 매개변수를 추가해줘" |
| **중간 저장** | 중요한 코드는 파일로 저장해두기 | 세션이 끊어져도 코드를 다시 제공 가능 |
| **코드 제공** | 새 세션에서는 기존 코드를 함께 전달 | "이 코드에서 이어서 작업해줘: ..." |

### 11.3 단계별 요청 전략

복잡한 프로그램을 만들 때 가장 효과적인 방법은 **단계별 요청**입니다. 한 번에 모든 기능을 요청하는 대신, 작은 단위로 나누어 하나씩 추가해 나가는 전략입니다. 각 단계에서 결과를 확인하고 방향을 조절할 수 있으므로, 최종 결과물이 훨씬 안정적입니다.

#### 단계별 요청의 원칙

1. **핵심 기능부터 시작하기**: 가장 기본적인 동작부터 만듭니다.
2. **한 번에 하나의 기능만 추가**: 여러 기능을 동시에 요청하면 혼란이 생깁니다.
3. **각 단계에서 실행 확인**: 새 기능을 추가할 때마다 실행해서 동작을 확인합니다.
4. **문제가 생기면 즉시 해결**: 다음 단계로 넘어가기 전에 현재 단계의 문제를 해결합니다.

---

**예제 11-3: "이전 코드에서..." 참조하기**

AI와 대화할 때 이전에 작성한 코드를 참조하는 방법은 매우 중요합니다. 구체적으로 참조하면 AI가 정확하게 이해하고, 모호하게 참조하면 엉뚱한 결과가 나올 수 있습니다.

```python
# examples/python/chapter03/ex11_03_reference_previous.py (일부 발췌)

def show_reference_patterns():
    """이전 코드 참조 패턴을 보여줍니다"""

    # 효과적인 참조 방법:
    good_examples = [
        ("구체적 함수 참조",
         "이전에 만든 calculate_total() 함수에 할인율 매개변수를 추가해줘"),
        ("구조 참조",
         "아까 만든 학생 딕셔너리에 '출석률' 필드를 추가해줘"),
        ("동작 참조",
         "방금 만든 코드에서 파일을 읽는 부분이 에러가 나. 예외 처리를 추가해줘"),
        ("단계 참조",
         "2단계에서 만든 정렬 기능을 역순 정렬도 가능하게 수정해줘"),
    ]

    # 비효과적인 참조 방법:
    bad_examples = [
        ("모호한 참조", "그거 수정해줘",
         "'이전에 만든 정렬 함수를 수정해줘'라고 구체적으로"),
```

**예제 11-4: 단계별 기능 추가 대화**

이 예제는 텍스트 분석기를 단계별로 만들어가는 과정을 보여줍니다. 1단계에서는 단어 수만 세고, 2단계에서 문장 수를 추가하고, 3단계에서 읽기 시간까지 계산합니다.

```python
# examples/python/chapter03/ex11_04_step_by_step_analyzer.py (일부 발췌)

SAMPLE_TEXT = """바이브 코딩은 AI와 함께 프로그래밍하는 새로운 방식입니다.
기존의 코딩은 개발자가 모든 코드를 직접 작성해야 했습니다. ..."""

# [1단계 대화] "텍스트에서 단어 수를 세는 프로그램 만들어줘"
def step1_word_count(text):
    words = text.split()
    return len(words)

# [2단계 대화] "여기에 문장 수도 세어줘"
def step2_sentence_count(text):
    words = text.split()
    word_count = len(words)
    sentence_count = sum(1 for char in text if char in ".!?")
    return word_count, sentence_count

# [3단계 대화] "읽기 시간도 계산해줘"
def step3_full_analysis(text):
    words = text.split()
    word_count = len(words)
    sentence_count = sum(1 for char in text if char in ".!?")

    # 한국어 평균 읽기 속도: 분당 약 500자
    char_count = len(text.replace(" ", "").replace("\n", ""))
    reading_time_seconds = (char_count / 500) * 60

    return {
        "단어 수": word_count,
        "문장 수": sentence_count,
        "글자 수(공백 제외)": char_count,
        "평균 문장 길이(단어)": round(word_count / sentence_count, 1),
        "예상 읽기 시간": f"{int(reading_time_seconds // 60)}분 {int(reading_time_seconds % 60)}초",
    }
```

```
  • AI가 이전 코드 구조를 유지하면서 기능을 추가합니다
  • 문제가 생기면 해당 단계만 수정하면 됩니다
```

주목할 점은 각 단계에서 이전 단계의 코드가 **그대로 유지**된다는 것입니다. 1단계에서 만든 단어 수 세기 로직이 2단계, 3단계에서도 동일하게 포함되어 있습니다. AI가 "여기에 ~ 추가해줘"라는 요청을 받으면, 기존 코드를 건드리지 않고 새로운 기능만 추가합니다.

#### 단계별 요청의 실전 패턴

복잡한 프로그램을 만들 때 권장하는 단계별 요청 순서입니다.

```
1단계: 핵심 기능 구현   → "~ 하는 프로그램 만들어줘"
2단계: 기능 확장       → "여기에 ~ 기능도 추가해줘"
3단계: 입력 검증       → "잘못된 입력을 처리해줘"
4단계: 출력 개선       → "결과를 보기 좋게 정리해줘"
5단계: 에러 처리       → "예외 상황을 처리해줘"
```

> **Tip:** 단계를 나눌 때는 "하나의 대화에 하나의 기능"을 원칙으로 삼으세요. "문장 수도 세고, 읽기 시간도 계산하고, 가장 긴 문장도 찾아줘"처럼 한꺼번에 요청하면 AI가 혼란스러워할 수 있습니다.

### 11.4 명확한 피드백 주기

AI와의 대화에서 **피드백**은 매우 중요한 역할을 합니다. AI가 생성한 코드에 대해 어떤 피드백을 주느냐에 따라 다음 결과물의 품질이 달라집니다. 피드백에는 크게 두 가지 종류가 있습니다.

#### 긍정적 피드백: "잘 됐어! + 추가 요청"

AI가 만든 결과가 마음에 들 때, 그 사실을 명확하게 알려주고 다음 요청을 이어가는 방식입니다.

```
"잘 됐어! 이제 여기에 색상 출력 추가해줘"
"멋져! 완료 시간도 표시해줘"
"좋아! 이번에는 파일 저장 기능도 넣어줘"
```

긍정적 피드백의 효과는 다음과 같습니다.
- AI가 **현재 방향이 올바르다**고 판단하고, 기존 코드를 유지합니다.
- 기존 코드를 변경하지 않고 **새 기능만 추가**하는 방향으로 응답합니다.
- 대화의 흐름이 자연스럽게 이어집니다.

**예제 11-5: 긍정적 피드백으로 프로그래스 바 발전시키기**

이 예제는 프로그래스 바를 만들면서 긍정적 피드백을 주는 과정을 보여줍니다. "잘 됐어!", "멋져!"라는 피드백으로 시작하면 AI가 기존 코드를 유지하면서 기능을 추가합니다.

```python
# examples/python/chapter03/ex11_05_positive_feedback.py (일부 발췌)

# [1차 대화] "프로그래스 바 만들어줘"
def basic_progress_bar():
    tasks = ["데이터 로딩", "분석 처리", "결과 생성", "보고서 작성", "완료 처리"]

    for i, task in enumerate(tasks, 1):
        progress = i / len(tasks)
        bar_length = 30
        filled = int(bar_length * progress)
        bar = "█" * filled + "░" * (bar_length - filled)
        percent = progress * 100
        print(f"  [{bar}] {percent:5.1f}% - {task}")


# [2차 대화] "잘 됐어! 이제 여기에 색상 출력 추가해줘"
class Color:
    RED = "\033[91m"
    GREEN = "\033[92m"
    YELLOW = "\033[93m"
    RESET = "\033[0m"

def colored_progress_bar():
    tasks = [
        ("데이터 로딩", Color.BLUE),
        ("분석 처리", Color.CYAN),
        # ... 색상이 추가된 버전
    ]


# [3차 대화] "멋져! 완료 시간도 표시해줘"
def full_progress_display():
    # 색상 + 시간 표시가 모두 포함된 최종 버전
    pass
```

AI가 만든 결과물이 마음에 들지 않을 때는 **무엇이 문제이고 어떻게 바꾸고 싶은지** 구체적으로 알려주어야 합니다. "다시 해줘"보다는 "출력 형식을 표로 바꿔줘"가 훨씬 효과적입니다.

**예제 11-6: 수정 요청 피드백으로 출력 형식 변경하기**

이 예제는 판매 데이터 분석 결과의 출력 형식을 피드백을 통해 단계별로 개선하는 과정을 보여줍니다.

```python
# examples/python/chapter03/ex11_06_format_change.py (일부 발췌)

SALES_DATA = [
    {"제품": "노트북", "1분기": 150, "2분기": 180, "3분기": 200, "4분기": 220},
    {"제품": "태블릿", "1분기": 90, "2분기": 110, "3분기": 95, "4분기": 130},
    {"제품": "스마트폰", "1분기": 300, "2분기": 280, "3분기": 320, "4분기": 350},
    {"제품": "이어폰", "1분기": 200, "2분기": 250, "3분기": 230, "4분기": 270},
    {"제품": "스마트워치", "1분기": 60, "2분기": 80, "3분기": 100, "4분기": 120},
]

# [1차 대화] "판매 데이터를 분석해서 보여줘"
def format_v1_basic(data):
    for item in data:
        total = item["1분기"] + item["2분기"] + item["3분기"] + item["4분기"]
        avg = total / 4
        print(f"  {item['제품']}: "
              f"1분기={item['1분기']}, 2분기={item['2분기']}, "
              f"3분기={item['3분기']}, 4분기={item['4분기']} "
              f"(합계: {total}, 평균: {avg:.0f})")

# [2차 대화] "출력 형식을 표로 바꿔줘"
```

### 11.5 대화 리셋과 재시작

대화가 꼬이거나, 원하는 방향과 완전히 다른 곳으로 흘러갈 때는 **대화를 리셋**하는 것이 효과적입니다. 잘못된 방향으로 10번 수정을 요청하는 것보다, 처음부터 다시 시작하는 것이 더 빠를 수 있습니다.

#### 대화를 리셋해야 하는 시점

다음과 같은 상황에서는 대화를 리셋하는 것을 고려해보세요.

1. **AI가 요청을 계속 오해할 때**: 같은 수정을 3번 이상 요청했는데도 원하는 결과가 나오지 않는 경우
2. **코드가 너무 복잡해졌을 때**: 기능을 추가하다 보니 코드가 스파게티처럼 얽힌 경우
3. **방향을 완전히 바꾸고 싶을 때**: 처음 요청한 것과 다른 접근 방식을 시도하고 싶은 경우
4. **세션이 너무 길어졌을 때**: 대화가 수십 번 이상 오가면서 AI의 응답 품질이 떨어지는 경우

#### 효과적인 리셋 방법

대화를 리셋할 때는 단순히 새 세션을 시작하는 것보다, **이전 대화에서 배운 것을 정리하여 새 세션에 전달하는 것**이 효과적입니다.

```
[새 세션에서의 요청]

"이전에 텍스트 분석기를 만들었는데, 처음부터 다시 만들고 싶어.
이번에는 다음 요구사항으로 만들어줘:

1. 텍스트를 입력받아 단어 수, 문장 수, 글자 수를 분석
2. 결과를 표 형식으로 출력
3. 읽기 시간을 분/초 단위로 계산
4. 입력 검증 포함"
```

이렇게 하면 이전 대화의 시행착오를 거치지 않고, 바로 원하는 결과물에 가까운 코드를 생성할 수 있습니다.

#### 리셋 시 체크리스트

대화를 리셋하기 전에 다음 사항을 확인하세요.

- [ ] 현재까지 만든 코드 중 **보존하고 싶은 부분**이 있는가?
- [ ] 이전 대화에서 **배운 요구사항**을 정리했는가?
- [ ] **실패한 접근 방식**을 기록해두었는가? (같은 실수를 반복하지 않기 위해)
- [ ] 새 대화에서 **더 구체적인 요청**을 할 수 있는가?

> **Tip:** 대화를 리셋하기 전에 현재까지의 코드를 파일로 저장해두세요. 새 세션에서 "이 코드를 기반으로 개선해줘"라고 하면서 코드를 붙여넣을 수 있습니다. 완전한 처음부터 시작하는 것보다 훨씬 효율적입니다.

### 11.6 긴 대화 관리하기

실전에서는 프로그램이 복잡해질수록 대화도 길어집니다. 20번, 30번 이상 대화를 주고받으면 AI의 컨텍스트 한계에 도달할 수 있고, 초기 대화 내용을 잊어버릴 수 있습니다. 긴 대화를 효과적으로 관리하는 방법을 알아봅니다.

#### 컨텍스트 창의 이해

AI에게는 **컨텍스트 창(context window)**이라는 한계가 있습니다. 이것은 AI가 한 번에 기억할 수 있는 텍스트의 양입니다.

```
┌──────────────────────────────────────┐
│            컨텍스트 창               │
│                                      │
│  [대화 1] [대화 2] ... [대화 N]      │
│                                      │
│  대화가 많아지면 앞쪽 대화가         │
│  밀려나서 잊혀질 수 있음             │
└──────────────────────────────────────┘
```

대화가 쌓이면 초기에 나눈 대화 내용이 컨텍스트 창 밖으로 밀려나, AI가 더 이상 기억하지 못할 수 있습니다.

#### 긴 대화 관리 전략

**전략 1: 중간 요약 요청하기**

대화가 길어지면 AI에게 현재까지의 작업 내용을 요약해달라고 요청합니다.

```
"지금까지 만든 프로그램의 기능을 정리해줘"
```

이렇게 하면 AI가 현재 상태를 다시 한번 정리하게 되고, 이후 대화에서도 정확한 컨텍스트를 유지할 수 있습니다.

**전략 2: 기능 단위로 세션 나누기**

하나의 긴 세션보다 여러 개의 짧은 세션이 효과적일 수 있습니다.

```
세션 1: 기본 기능 구현 (대화 5-7회)
→ 코드를 파일로 저장

세션 2: UI 개선 (대화 5-7회)
→ 세션 1의 코드를 제공하고 시작

세션 3: 에러 처리 추가 (대화 5-7회)
→ 세션 2의 코드를 제공하고 시작
```

**전략 3: 현재 코드 상태 공유하기**

대화가 10회를 넘어가면, AI에게 현재 코드의 전체 내용을 다시 보여주면서 다음 요청을 하는 것이 안전합니다.

```
"현재 코드 전체를 보여줄게. 이 코드에서 ~ 기능을 수정해줘:

[현재 코드 전체 붙여넣기]"
```

**전략 4: 대화 회차 번호 붙이기**

대화가 여러 회에 걸쳐 진행될 때, 직접 번호를 붙여가며 관리하면 참조가 쉬워집니다.

```
[요청 1/5] "기본 데이터 구조를 만들어줘"
[요청 2/5] "데이터를 추가하는 함수를 만들어줘"
[요청 3/5] "데이터를 검색하는 함수를 만들어줘"
[요청 4/5] "데이터를 수정하는 함수를 만들어줘"
[요청 5/5] "메인 메뉴를 만들고 모든 기능을 연결해줘"
```

#### 대화 관리 권장 가이드라인

| 대화 횟수 | 상태 | 권장 행동 |
|-----------|------|-----------|
| 1~5회 | 쾌적 | 자유롭게 대화 이어가기 |
| 6~10회 | 주의 | 중간 요약 요청, 코드 저장 |
| 11~15회 | 경고 | 현재 코드 전체 재공유 고려 |
| 16회 이상 | 위험 | 세션 분리 또는 리셋 검토 |

> **Tip:** Claude Code 같은 CLI 기반 AI 도구를 사용할 때는 코드가 파일 시스템에 직접 저장되므로, 컨텍스트 관리가 비교적 수월합니다. AI가 항상 파일의 현재 상태를 읽을 수 있기 때문입니다. 반면 웹 기반 채팅 인터페이스에서는 컨텍스트 관리에 더 신경을 써야 합니다.

### 정리

이 장에서 우리는 AI와 효과적으로 대화하는 기술을 배웠습니다. 핵심 내용을 정리하면 다음과 같습니다:

1. **단일 요청 vs 대화형 개발**: 한 번의 요청보다 여러 번의 대화를 통해 점진적으로 개발하면 결과물의 품질이 크게 향상됩니다.
2. **컨텍스트 유지**: 같은 세션 안에서 대화를 이어가면 AI가 이전 코드를 기억하고, 일관성 있게 기능을 확장할 수 있습니다.
3. **구체적 참조**: "그거 수정해줘" 대신 "이전에 만든 calculate_total() 함수를 수정해줘"처럼 구체적으로 참조하면 AI가 정확하게 이해합니다.
4. **단계별 요청**: 복잡한 프로그램은 핵심 기능부터 시작하여 한 번에 하나의 기능을 추가하는 전략이 효과적입니다.
5. **명확한 피드백**: 긍정적 피드백("잘 됐어! + 추가 요청")과 구체적인 수정 피드백("출력 형식을 표로 바꿔줘")을 적절히 활용합니다.
6. **대화 리셋**: 대화가 꼬이면 과감하게 리셋하되, 이전 대화에서 배운 것을 정리하여 새 세션에 전달합니다.
7. **긴 대화 관리**: 중간 요약 요청, 기능 단위 세션 분리, 현재 코드 재공유 등의 전략으로 장시간 대화를 관리합니다.
